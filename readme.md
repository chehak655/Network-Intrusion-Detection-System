# 🛡️ AI-Based Network Intrusion Detection System

Real-time network traffic classification using flow-based machine learning — built as an industrial training project at **Bharat Heavy Electricals Limited (BHEL), Haridwar**.

The system captures live packets, reconstructs them into bidirectional network flows, extracts 68 CICFlowMeter-equivalent statistical features per flow, and classifies each one using a supervised XGBoost model (specific attack types) alongside an unsupervised Isolation Forest model (novel/unknown anomalies) — surfaced through a live web dashboard.

---

## Features

- **Live packet capture** with Scapy — no offline pcap replay required
- **Stateful flow reconstruction** — groups raw packets into bidirectional flows with proper inactivity timeout handling
- **68 statistical features per flow** (packet length distributions, inter-arrival times, TCP flags, window sizes, active/idle timing) — matched 1:1 against the CIC-IDS2017 training columns, so live predictions reflect trained accuracy rather than degrading silently
- **Dual-model detection**
  - XGBoost multi-class classifier — identifies specific attack types (DDoS, PortScan, Bot, Brute Force, Web Attack, etc.)
  - Isolation Forest — flags anomalous traffic that doesn't match any known attack signature
- **MySQL persistence** of every detection
- **Live dashboard** (Flask + Plotly) — auto-refreshing stats, attack/protocol distribution charts, traffic timeline, top talkers, searchable/filterable detection log, network risk level
- **CSV and PDF export** of detection records

```
        │
        ▼

        │
        ▼
ML Inference               XGBoost classifier + Isolation Forest anomaly detector
        │
        ▼

        │
        ▼
Flask + Plotly Dashboard  (search, charts, CSV/PDF export)
```

## Getting started

### 1. Prerequisites

- Python 3.10 / 3.11
- MySQL Server
- **Windows:** [Npcap](https://npcap.com/#download) with "WinPcap API-compatible mode" enabled
- **Linux/Mac:** raw socket access (see note on `sudo`/`setcap` below)

### 2. Setup

```bash
git clone <repo-url>
cd NETWORK_INTRUSION_DETECTION

python -m venv venv
source venv/bin/activate        # Windows: venv\Scripts\activate

pip install -r requirements.txt
```

### 3. Configure the database

```sql
CREATE DATABASE network_ids;
```

```bash
cp .env.example .env
# then edit .env with your real MySQL credentials
```

### 4. Train the models

Dataset CSVs must already be in `dataset/`.

```bash
python training/data_analysis.py          # optional sanity check
python training/data_preprocessing.py
python training/create_balanced_dataset.py
python training/train_initial_xgboost.py

cd training
python feature_selection.py
cd ..

python training/train_final_xgboost.py
python training/train_isolation_forest.py
```

### 5. Verify the live pipeline

```bash
python flows/test_feature_extractor.py   # should end with "Missing: None - OK"
python detection/test_predictor.py       # should end with "no gaps - OK"
python test_database.py                  # confirms MySQL connectivity
```

### 6. Run it

```bash
# Terminal 1 — capture + inference engine (needs elevated permissions to sniff packets)
sudo venv/bin/python main.py        # Windows: run terminal as Administrator

# Terminal 2 — dashboard
python app.py
```

Open **http://127.0.0.1:5000** to view the live dashboard.

> **Linux tip:** instead of running `main.py` as root every time, grant capture capability once:
> `sudo setcap cap_net_raw,cap_net_admin=eip $(readlink -f venv/bin/python)`

## Dataset

Trained on [CIC-IDS2017](https://www.unb.ca/cic/datasets/ids-2017.html) (Canadian Institute for Cybersecurity) — five days of labeled traffic covering benign activity plus DoS, DDoS, PortScan, Brute Force (FTP/SSH-Patator), Web Attack, Infiltration, and Botnet categories.

---

## Notes on feature parity

A core design goal of this project: the **live feature extractor produces the exact same named features** the models were trained on (`Flow Bytes/s`, `Fwd IAT Mean`, `Init_Win_bytes_forward`, etc.), rather than a differently-named custom feature set that would silently zero-fill at inference time. `training/feature_selection.py` enforces this by filtering candidate features against `FeatureExtractor.LIVE_FEATURE_NAMES` before any feature is allowed into the final model — so a feature can never be selected for training that the live system can't actually compute.

## Deployment

For running continuously rather than in a terminal:

- Disable Flask debug mode (`app.run(debug=False)`) before exposing the dashboard beyond localhost
- Run `main.py` and `app.py` as background services (systemd on Linux, Task Scheduler/NSSM on Windows)
- Use a dedicated low-privilege MySQL user rather than `root`
- Put the dashboard behind a reverse proxy (Nginx) + production WSGI server (Gunicorn/Waitress) if accessed by others on the network
- Position the capture host on a SPAN/mirror port if monitoring traffic beyond its own interface
